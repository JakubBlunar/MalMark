# Malmark privacy

Malmark stores OAuth credentials, profile information, preferences, per-domain CSS selectors, MAL matching rules and pending episode updates in the browser’s extension storage. Credentials are not synced to another browser or device. Active tabs use session storage. Watched timeline ranges for matched episodes are saved locally per MAL account, website, series and episode so progress survives page refreshes and closing the browser, including episodes already logged on MAL. These checkpoints expire after 30 days of inactivity, retain at most 100 episodes and are removed when their custom website is removed or their match/episode is corrected. Pending updates expire after seven days.

Connecting sends authentication requests to MyAnimeList. Detecting an anime sends its title to the official MAL API to search for a match. Manual searches, profile/detail requests and approved list updates also go to MAL. Cover/profile images are loaded from URLs returned by MAL. There is no analytics service or Malmark backend.

GitHub/unpacked builds ask for your own public MAL client ID and keep it in local extension storage. Store builds bundle the publisher’s public client ID. Each person signs in to their own MyAnimeList account and receives separate account tokens. A client ID does not grant access to anyone’s list on its own, and no client secret is shipped or requested.

Built-in access is limited to Crunchyroll and MAL. Crunchyroll is the only built-in streaming integration. Netflix and other websites require an explicit domain permission and selector setup; embedded players require separate optional domain access. Optional permission patterns in the manifest permit requesting a specific HTTPS origin, but do not grant access to every website.

Only extension UI pages can approve a MAL list change. The content scripts read selected title/episode elements and accessible HTML5 playback state; they never receive OAuth tokens. Episode reminders embed a packaged extension frame with Update progress and Later buttons; approval is restricted to that queued update using a short-lived grant for the current tab and account. Later hides the reminder while keeping the update queued in Malmark for up to seven days. A website setup session can save selectors only for its original tab and origin with a short-lived setup nonce.

Use **Disconnect account** to remove stored credentials, playback checkpoints, session data and queued updates. Your public client ID, saved matches and website configurations remain available locally; edit the client ID from the sign-in screen, and remove matches and websites under **Matches** and **Sites**. Player permissions can be removed in **Settings**. Uninstalling Malmark removes its extension storage. Reload already-open pages after removing a site or player permission to unload injected scripts.

Malmark uses and transfers user data only to provide its anime tracking and MyAnimeList features, in accordance with the Chrome Web Store User Data Policy, including its Limited Use requirements. It does not sell user data, use it for advertising, transfer it to data brokers, or use it to assess creditworthiness. The developer does not receive a copy of your tokens, profile or watch history. MyAnimeList and streaming providers process requests to their own services under their respective policies.

Support: [Malmark issues](https://github.com/JakubBlunar/MalMark/issues). Public issues should not include OAuth tokens, authorization codes, passwords or private watch-history exports.
